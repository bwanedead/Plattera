# Transcript Edit Blocker Transition Guardrail

Date: March 10, 2026
Status: Active architecture guardrail

## Principle Freeze

- Fixed decision keys are transitional scaffolding, not the long-term blocker ontology.
- Convention menus are suggestions, never mandates.
- Ad hoc blockers must remain possible at all times.
- Closure classes remain runtime-owned engine primitives.

## Ownership Model

Runtime owns:
- blocker schema
- lifecycle legality
- persistence
- guardrails
- HITL lifecycle
- terminalization
- closure classes

Agent owns:
- convention identification
- blocker discovery
- blocker selection
- blocker updates/closure proposals
- ad hoc blocker creation intent

Scaffolding owns:
- convention-situated blocker archetype menus
- hints only

## Migration Rule

- Run emergent blockers in parallel with fixed-key scaffolding until parity is demonstrated.
- Do not remove fixed-key fallback until emergent focus selection and blocker-class terminalization are validated in live runs.
