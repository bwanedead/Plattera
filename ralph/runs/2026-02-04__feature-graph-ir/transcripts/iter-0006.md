## Issues encountered and resolutions

### Issue 1: Import triggers alignment service dependency
**Problem:** Importing from `services.feature_graph` triggered `services/__init__.py` which imports alignment service (requires nltk, not available in env).

**Resolution:** Used direct import with sys.path manipulation to bypass services package init.

### Issue 2: Model signature mismatches
**Problem:** Test data used incorrect field names and signatures from early drafts.

**Resolution:** Read actual models (models.py, artifacts.py, gaps.py) and corrected all test data to match:
- FeatureNode.id (not node_id)
- FeatureGraph.graph_id required
- Literal requires raw + value
- JudgeReport requires graph_id
- Updated all constructor calls to match actual signatures

### Issue 3: Test index pollution
**Problem:** Tests were sharing a single index (dossiers_state_root()), causing failures due to artifacts from previous tests.

**Resolution:** Added `state_dir` parameter to service constructor and ensured each test uses isolated temp directories for both artifacts and state.

## Design notes

### Architectural consistency
- Followed existing schema_persistence_service patterns for familiarity
- Atomic writes with tempfile + os.replace ensures crash-safety
- Index-based queries avoid filesystem scans

### Separation from legacy
- Feature graph artifacts stored separately from schema/georef artifacts
- Path: `dossiers_data/artifacts/feature_graphs/` (not in `processing_jobs/`)
- This maintains PRD constraint: "not replacing or refactoring existing pipelines"

### Test isolation
- Optional root and state_dir parameters enable temp directory testing
- Each test creates isolated service instance with dedicated temp dirs
- No shared state between tests (deterministic, reproducible)
